# AIOK web interface

A responsive, sidebar-free university information assistant intended for information and assistance offices. The interface focuses on requirements, policies, and services from a locally maintained knowledge base, with a centered conversation and light/dark themes.

## Run locally

From `aiok_ui`, run:

```sh
npm install
npm run dev
```

Use the local URL printed by Vite. `npm run build` builds the production app; `npm run lint` checks the source.

## Preview behavior

This is an interactive UI preview. Responses are explicitly labeled sample content, generated by `previewResponse` in `src/App.jsx`. The existing Python terminal chatbot is not connected to this frontend. Replace `generate` with a backend request and wire cancellation to that request when adding a web API.

- Enter sends; Shift+Enter inserts a new line.
- Suggestion cards populate the composer for editing before sending.
- Stop cancels the pending preview response. The last completed response can be regenerated.
- Responses support basic Markdown paragraphs, bold text, lists, tables, and fenced code. Copy controls use the browser clipboard.
- Voice input uses the browser's speech recognition service where supported and requires microphone permission. It may use a browser-provider remote service.
- Settings offer theme selection and Markdown conversation export. Theme preference is saved locally; conversations and feedback remain in memory for the current session.

The interface uses native controls, accessible button labels, keyboard focus styles, a modal settings dialog, and reduced-motion support. No external fonts or image services are required.

## Knowledge-base integration expectations

The suggestion topics reflect documents in the repository: graduation requirements, student insurance, and merchandise-selling guidelines. They do not establish that a policy is current or that the frontend can retrieve it. Office routing also requires verified directory information.

When connecting the Python retrieval backend, answers should cite the retrieved document and page where available, distinguish academic years and document versions, and explain when the saved material does not answer a question. Do not invent office locations, contacts, deadlines, or requirements. If information is missing, direct the visitor to the university information or assistance office. Keep knowledge-base maintenance separate from the visitor chat interface.
